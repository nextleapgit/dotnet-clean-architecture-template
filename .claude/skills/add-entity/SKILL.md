# Add a Domain Entity

Create a new entity and wire it through every layer, following `TodoItem`.

## Files to create/modify

1. **Entity** — `src/CleanArchitecture.Domain/{Feature}/{Entity}.cs`

```csharp
using CleanArchitecture.SharedKernel;

namespace CleanArchitecture.Domain.Projects;

public sealed class Project : Entity
{
    public const int NameMaxLength = 200;

    private Project()
    {
    }

    public Guid Id { get; private set; }
    public TenantId TenantId { get; private set; }
    public Guid OwnerId { get; private set; }
    public string Name { get; private set; }
    public DateTime CreatedAtUtc { get; private set; }

    public static Project Create(TenantId tenantId, Guid ownerId, string name, DateTime createdAtUtc)
    {
        var project = new Project
        {
            Id = Guid.CreateVersion7(),
            TenantId = tenantId,
            OwnerId = ownerId,
            Name = name,
            CreatedAtUtc = createdAtUtc
        };

        project.Raise(new ProjectCreatedDomainEvent(project.Id));

        return project;
    }

    public void Rename(string name)
    {
        Name = name;

        Raise(new ProjectRenamedDomainEvent(Id));
    }
}
```

Rules: `sealed`, inherits `Entity`, **private setters** (an architecture test rejects public ones), private constructor for EF, a `Create` factory raising the `Created` event, a behavior method per state change, public length constants. Tenant-owned entities carry `TenantId` (only global platform metadata may omit it). Collections initialize with `= [];`.

2. **Errors** — `{Entity}Errors.cs`, codes `"{FeaturePlural}.{Reason}"`, factory by semantics: `Problem` (400), `Unauthorized` (401), `Forbidden` (403), `NotFound` (404), `Conflict` (409), `Failure` (500, unexpected only).

3. **Domain events** — one sealed record per file, `{Entity}{PastTense}DomainEvent(Guid {Entity}Id) : IDomainEvent`. Events carry ids, not entities.

4. **Store interface** — `src/CleanArchitecture.Application/{Feature}/I{Entity}Store.cs`. Reads take `TenantId` explicitly; no `IQueryable` or EF types leak out.

```csharp
public interface IProjectStore
{
    Task<Project?> FindAsync(TenantId tenantId, Guid projectId, CancellationToken cancellationToken);
    void Add(Project project);
}
```

5. **Store + EF configuration** — `src/CleanArchitecture.Infrastructure/{Feature}/`:

```csharp
internal sealed class ProjectStore(ApplicationDbContext dbContext) : IProjectStore
{
    public Task<Project?> FindAsync(TenantId tenantId, Guid projectId, CancellationToken cancellationToken) =>
        dbContext.Projects.SingleOrDefaultAsync(p => p.TenantId == tenantId && p.Id == projectId, cancellationToken);

    public void Add(Project project) => dbContext.Projects.Add(project);
}

internal sealed class ProjectConfiguration : IEntityTypeConfiguration<Project>
{
    public void Configure(EntityTypeBuilder<Project> builder)
    {
        builder.HasKey(p => p.Id);
        builder.Property(p => p.Name).HasMaxLength(Project.NameMaxLength);
        builder.HasIndex(p => p.TenantId);
        builder.HasOne<Tenant>().WithMany().HasForeignKey(p => p.TenantId);
        builder.HasOne<User>().WithMany().HasForeignKey(p => p.OwnerId);
    }
}
```

`TenantId` conversion is global (`ConfigureConventions`); don't configure it per entity.

6. **Wiring** — add `DbSet<Project> Projects` to `ApplicationDbContext` and `services.AddScoped<IProjectStore, ProjectStore>()` in Infrastructure `AddDatabase`.

7. **Unit-test fake** — `tests/CleanArchitecture.UnitTests/Fakes/InMemoryProjectStore.cs` implementing the same interface with the same tenant filtering.

8. **Migration** — from the repo root (the tool is pinned in `dotnet-tools.json`):

```
dotnet tool restore
dotnet ef migrations add Add_Projects --project src/CleanArchitecture.Infrastructure --startup-project src/CleanArchitecture.Api --output-dir Database/Migrations
```

Prefix new migration files with `// <auto-generated />`. Review tenant ids, indexes, uniqueness, delete behavior, and nullability before committing. Never edit the hand-written audit trigger block in `InitialCreate`.

## Rules

- Domain references only `SharedKernel`. EF Core exists only in Infrastructure.
- Run `dotnet build` and `dotnet test --solution CleanArchitecture.slnx`; architecture tests enforce the rules above.
- For use cases on the entity, continue with the `add-feature` skill.
