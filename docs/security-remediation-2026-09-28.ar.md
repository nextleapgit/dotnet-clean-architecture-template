# معالجة ملاحظات المراجعة الأمنية — 28 سبتمبر 2026

نُفذت إصلاحات R01–R11 في الحل الأساسي. لم تُنشر التغييرات على خادم إنتاج، ولم يُعدَّل المشروع المستقل `nextleapoperations`.

| الملاحظة | المعالجة |
|---|---|
| R01: استمرار Access Token بعد إبطال الجلسة | يفحص التحقق من الـ JWT جلسة فعالة تطابق المستخدم و`session_id` (`SessionValidator`)، ويفحص التفويض المستخدم والمستأجر. تسجيل الخروج وإعادة تعيين كلمة المرور واكتشاف إعادة استخدام Refresh Token تمنع الطلبات المحمية التالية بالرموز القديمة. |
| R02: بقاء رابط استعادة قديم | تُستهلك روابط الاستعادة الصالحة عند تغيير كلمة المرور أو إعادة تعيينها ضمن المعاملة نفسها. |
| R03: مفاتيح البريد مكشوفة داخل قاعدة البيانات | تشفيرها بشهادة RSA خارج القاعدة، مع دعم شهادات سابقة لفك التشفير. تُغلَّف المفاتيح القديمة عند بدء التشغيل مع الحفاظ على معرفاتها وإمكانية قراءة الرسائل الموجودة. |
| R04: روابط صالحة متعددة عند التزامن | قفل صف المستخدم خلال إصدار الروابط واستهلاكها وتغيير بيانات الدخول، وإعادة قراءة الرمز بعد الحصول على القفل. تشترك عمليات تحديث الجلسة والخروج وتعطيل الحساب في القفل نفسه. |
| R05: تجاوز الطلبات المرفوضة لمحدد المعدل | أصبح المحدد بعد المصادقة وقبل التفويض. استجابة 429 تتضمن معرّف التتبع و`Retry-After` عند توفره. |
| R06: قيمة SMTP مجهولة تؤدي لاتصال غير مشفر | رفض القيم غير المعرّفة عند بدء التشغيل وفي المرسل نفسه. |
| R07: خدمات التطوير مكشوفة للشبكة | ربط جميع منافذ Docker Compose المنشورة بالعنوان `127.0.0.1`. |
| R08: ملفات غير مقصودة داخل حزمة القالب | قوائم إدراج صريحة للتغليف والتوليد، وفحص محتوى الحزمة في CI قبل توزيعها. |
| R09: قراءات ومدخلات غير محدودة | صفحات للمهام، وحدود للوسوم ومدخلات المصادقة، وحد جسم الطلب 64 KiB، ومنع تجاوز أعداد الصفحات. |
| R10: بيانات قديمة بين نسخ التطبيق | قراءة تفاصيل المهام مباشرة من PostgreSQL وإزالة الكاش المحلي واعتماده غير المستخدم. |
| R11: حالة صحة بريد غير دقيقة | رصد الطابور عند تعطيل العامل، والحجوزات المنتهية، والرسائل المعلقة غير القابلة للإرسال، والفشل أو الانتهاء خلال آخر 24 ساعة. |

## متطلبات الترقية

- **الإنتاج يحتاج شهادة:** اضبط `DataProtection__CertificatePath` و`DataProtection__CertificatePassword` من مصدر أسرار مناسب. يجب أن تشترك نسخ التطبيق في شهادة التشفير وشهادات فك التشفير السابقة. يرفض التطبيق بدء التشغيل خارج Development دون شهادة صالحة.
- خذ نسخة احتياطية قبل الترقية، واحفظ الشهادة منفصلة عن القاعدة. نسخ التطبيق القديمة لا تقرأ المفاتيح بعد تغليفها؛ نسّق الترقية بين جميع النسخ. لا يمكن لتعديل الكود استرجاع سرية نسخة تاريخية سُرّبت بالفعل.
- التطوير يولد شهادة محلية مستبعدة من Git والحزمة ويحفظها Compose في volume مستقل. لا تستخدمها للإنتاج.
- قائمة المهام تعيد افتراضياً 50 عنصراً وتقبل حتى 100 لكل صفحة: `GET /api/v1/todos?page=1&pageSize=50`. على العميل جلب الصفحات التالية عند الحاجة.
- الجلسة الملغاة تفشل في المصادقة وتعيد 401، مثل JWT المفقود أو غير الصحيح، ليعرف العميل أن عليه تسجيل الدخول من جديد. تبقى 403 للمستخدم المصادَق الذي لا يملك الصلاحية. تغيير كلمة المرور يحافظ على الجلسة الحالية فقط، وإعادة تعيينها تلغي جميع الجلسات.
- محدد المعدل محلي لكل نسخة؛ التوسع الأفقي يحتاج حداً مشتركاً عند البوابة. يجب أن تفحص المراقبة حالة البريد داخل استجابة `/health`، لأن `Degraded` لا تعني بالضرورة HTTP 503. مسار الجاهزية بقي خاصاً بقاعدة البيانات.

التفاصيل التشغيلية في [دليل التقوية والترقية](security-hardening.md)، والحالة السابقة في [المراجعة الأصلية](project-review-2026-09-27.ar.md).

## التحقق

أضيفت اختبارات دائمة لإبطال الجلسات والروابط القديمة، والطلبات المتزامنة، والتشفير بعد إعادة التشغيل، وترقية المفاتيح القديمة دون فقد الرسائل، والتحقق من SMTP، وحد الطلبات المرفوضة، وحد الجسم عبر Kestrel، وصفحات المهام واتساقها بين نسختين، وحالات تعطل طابور البريد.

سجلات التحقق المحلية محفوظة في `artifacts/security-review/` ومستبعدة من توزيع القالب.

المعالجة تخص العيوب المحددة في المراجعة، ولا تعني خلو النظام من كل ثغرة ممكنة. MFA وإدارة الجلسات من الواجهة وترقية نظام الهوية واختبارات الحمل والبنية الإنتاجية تبقى تحسينات مستقلة.
